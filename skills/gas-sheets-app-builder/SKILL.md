# GAS Sheets App Builder

Google Sheets をコンテナとする GAS アプリを、入力確認から実機テストまで一貫して完成させる。

## 対象者と案内方針

- 初めてGASアプリを作る非エンジニアを主な対象とする。専門用語は初出時に短く説明する。
- 一度に依頼するユーザー操作は1つにし、クリック場所、入力内容、完了の見分け方を示す。
- コマンドやエラーの全文を読める前提にせず、ユーザーが判断する必要のある部分だけ平易な日本語で伝える。
- 内部の実装判断はエージェント側で行い、選択結果がアプリの用途を変える場合だけ質問する。
- このスキルは明示呼び出し専用とする。一般的なGAS相談、既存プロジェクトの修正、用語質問には適用しない。

## ブラウザ自動操作を使わない

- 既定ではBrowser、Chrome、Playwright、Computer Useなどによるブラウザ自動操作を使わない。ユーザーがその依頼で明示的に許可・指定した場合だけ使用する。
- Driveの親確認、移動、リネームはDrive APIまたは利用可能なGoogle Driveコネクタで行い、IDとメタデータで検証する。
- OAuth同意画面、Apps Scriptエディタでの初回関数実行、スプレッドシート上のメニュー・UI確認は、必要なURLと短い操作手順をユーザーへ渡し、完了報告を待つ。
- ブラウザ自動操作なしでは確認できない項目を「確認済み」と報告しない。自動検証済み、ユーザー確認済み、未確認を分けて記録する。

## 1. 必要情報を集める

Chrome拡張が生成した初期プロンプトを渡された場合は、その内容を構造化して使い、記載済みの項目を質問し直さない。

初期プロンプトがない場合は、不足している項目だけを質問する。最初の質問では次の項目をまとめ、回答しやすい例を添える。

1. 参照スプレッドシートのURL（複数可）
2. 作業用Google DriveフォルダのURLまたはID
3. アプリ名。未指定なら作業フォルダ名を使う
4. UI形式: モーダル、サイドバー、モードレス、外部アプリ
5. 実現したいこと・操作の要件

質問文と要件例は [references/intake-examples.md](references/intake-examples.md) を読む。URLとIDが与えられたら、必要に応じて `scripts/parse_google_resource.py` で正規化する。

明示されたアプリ名を作業スプレッドシート名とApps Scriptプロジェクト名に使う。アプリ名がなければ作業フォルダ名を既定値にし、どちらも取得できない場合だけ名前を質問する。

Chrome拡張の入力に参照シートの名称が含まれていても任意の説明ラベルとして扱い、処理には依存しない。実際のタブ名はURLの `gid` とスプレッドシートのメタデータから確認する。営業、経理、在庫、人事など特定業務を前提にしない。

## 2. 実装前に確認する

- claspコマンドを実行する前に [references/clasp-compatibility.md](references/clasp-compatibility.md) を読み、`scripts/clasp_preflight.py` でNode、claspの版、コマンド体系、ログイン状態を確認する。
- グローバルclaspに依存せず、原則としてプロジェクトローカルに版を固定する。既存の`package.json`とlockfileがあれば尊重し、勝手に更新しない。
- カレントディレクトリの既存ファイルとGit状態を確認し、ユーザーの変更を上書きしない。
- 既存の`.clasp.json`と同名ファイルを確認し、作成済みプロジェクトを重複作成しない。
- 参照スプレッドシートを読み取り専用で調査し、対象タブ、ヘッダー、データ型、行数、空欄や表記揺れを把握する。
- URL内の `gid` があれば対象タブ特定の手掛かりにする。`gid` をシート名として扱わない。
- 要件の解釈が結果を大きく変える場合だけ追加質問する。それ以外は合理的な仮定を明示して進める。

認証、Driveへのファイル作成・移動、`clasp push` は外部状態を変更する。ユーザーの依頼範囲内で進め、環境が承認を要求したらその場で承認を求める。

## 3. バインドプロジェクトを作る

原則として次の順序で実行する。

1. `clasp create --type sheets --title "<アプリ名>"`（clasp v3では`create-script`も可）でバインドScript付きスプレッドシートを作成する。この時点では保存先フォルダを指定しない。
2. `.clasp.json` の `scriptId` と作成されたスプレッドシートIDを記録する。
3. Drive上の親フォルダを実際に確認する。指定フォルダ外ならDrive APIまたは利用可能なGoogle Driveコネクタで移動する。どちらも使えない場合は、UI非依存の初期設定関数を実装・pushし、ユーザーへ実行を依頼する。
4. フォルダ名、スプレッドシート名、Scriptプロジェクト名を揃える。
5. 1枚目のシート名をアプリ名に変更する。ただし要件で別名が明示されている場合は従う。

上記1では、作業用DriveフォルダIDを`--parentId`へ渡してはならない。claspの`--parentId`は既存のGoogle Sheets/Docs/Slides/FormsファイルにスクリプトをバインドするためのIDであり、保存先フォルダ指定ではない。新しいスプレッドシートを作る場合は`--type sheets`を使い、作成後にDrive APIまたは利用可能なコネクタで指定フォルダへ移動する。既存スプレッドシートへバインドする場合だけ`--parentId <スプレッドシートID>`を使い、`--type`と併用しない。

`clasp create` の出力だけで移動完了と判断せず、Driveの親フォルダをメタデータで検証する。タイトルだけを根拠に移動やリネームをしない。

## 4. 最小の動作品を実装する

- 標準構成は `Code.gs`、`appsscript.json`、用途別に分割したHTMLファイルとする。
- 参照シートは `SpreadsheetApp.openById()` で開く。IDを一か所の設定値にまとめる。
- `onOpen()` では業務用メニューと「開発用」サブメニューの登録だけを行う。Drive操作、外部シート読取、リネームなど認可や書き込みを伴う処理を混ぜない。
- Apps Scriptエディタから最初に実行する初期設定・OAuth用関数は`SpreadsheetApp.getUi()`、`alert()`、`showModalDialog()`に依存させず、結果を値として返す。メニューから通知を表示したい場合は、その関数を呼ぶ別のUIラッパーを用意する。
- UIは指定形式に合わせる。モーダルは `showModalDialog`、サイドバーは `showSidebar`、モードレスは `showModelessDialog` を使う。外部アプリは `doGet()` とWebアプリ構成を使い、公開範囲とデプロイ権限を実行前に確認する。
- サーバー側でデータを正規化・集計し、クライアント側は表示と操作に集中させる。
- 読み込み中、空データ、権限不足、参照先不正、予期しない列構成を平易な日本語で表示する。
- 日付と金額はスプレッドシートのタイムゾーン・ロケールを考慮する。
- `appsscript.json` には実際に必要な最小限の `oauthScopes` と高度なサービスだけを追加する。
- 要件外の書き込み、削除、共有設定変更、トリガー作成、デプロイは行わない。

最初の版では中核フローを優先する。装飾や高度な最適化より、実データで起動して主要操作が完了する状態を先に作る。

## 5. 検証して引き渡す

[references/delivery-checklist.md](references/delivery-checklist.md) に従って検証する。

最低限、次を完了する。

1. ローカルの構文・設定を確認する。
2. 事前診断が示したファイル状態確認コマンド（clasp v3は`show-file-status`、v2は`status`）でpush対象を確認する。
3. `clasp push` を実行する。
4. Script URLとスプレッドシートURLをユーザーへ渡す。ユーザーが明示的に求めた場合だけ、事前診断が示したopenコマンドを実行する。
5. 最小構成をpushした段階で、ユーザーへUI非依存の専用初期設定・認可関数の実行を依頼し、OAuth認可の完了報告を待つ。
6. ユーザーへスプレッドシートの再読み込み、業務用メニュー、「開発用」メニューの確認を依頼する。
7. ユーザーへUI起動、参照データ、主要操作、エラー表示の受入確認手順を渡し、結果を記録する。

初回push後に再読み込みしてもメニューが出ない場合は、対象スプレッドシートの「拡張機能 → Apps Script」からエディタを開き、表示されたScript IDが記録済みIDと一致することを確認してから、そのコンテナ文脈で`onOpen()`を一度実行するようユーザーへ案内する。Scriptエディタの直リンクだけを使ってUI関数を実行しない。

最後に、作成したスプレッドシートURL、Script ID、実装内容、確認結果、残っている制約だけを簡潔に報告する。認証情報、OAuthトークン、`.clasprc.json` は表示・保存・コミットしない。
